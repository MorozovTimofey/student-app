## Supabase как база данных и сервер

- **Что сделал:** создал проект Supabase, таблицы profiles, courses, course_members, lessons, тестовые данные; подключил приложение к базе и вывел пары на экран.
- **Где в коде:** supabase/schema.sql, supabase/seed.sql, src/lib/supabase.ts, src/app/index.tsx, .env
- **Почему так:** Supabase даёт PostgreSQL, вход и хранилище файлов без своего сервера — для одного разработчика это реально сделать за 2 недели. Схема хранится в schema.sql, чтобы структура базы была в репозитории.
- **Связи:** lessons.course_id → courses.id (один ко многим); course_members связывает студентов и дисциплины (многие ко многим).
- **Безопасность:** RLS включена на всех таблицах. Временное правило — чтение пар и дисциплин для всех; после входа ограничу доступ по роли и записи на курс. Publishable key публичный, безопасность держится на RLS; secret key в приложении не используется.

### Проблемы и решения

1. **`Cannot find native module 'ExpoSQLite'` в Expo Go** → заменил expo-sqlite на AsyncStorage для хранения сессии: он работает в Expo Go без отдельной сборки.
2. **`window is not defined` в веб-версии** → веб собирался на сервере (Node.js), где нет window; переключил `web.output` в app.json на `"single"`, теперь веб собирается в браузере.
3. **`supabaseKey is required`** → имя переменной в .env не совпадало с кодом; переименовал в EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY.
4. **Ошибка тёмной темы NativeWind в вебе** → добавил `darkMode: "class"` в tailwind.config.js.

### Чему научился

- Время из базы приходит строкой в UTC; форматирую его своей функцией formatTime, вынесенной из компонента.
- Связь таблиц позволяет найти название дисциплины по course_id.

## Вход и роли

- **Что сделал:** вход по почте и паролю, профиль с ролью студент/преподаватель, распределение по экранам по роли, выход, правила RLS по роли и записи на курс.
- **Где в коде:** src/lib/auth.tsx, src/app/_layout.tsx, src/app/index.tsx, src/app/login.tsx, src/app/student/, src/app/teacher/, supabase/schema.sql, supabase/seed.sql
- **Почему так:**
  - Профиль создаётся триггером handle_new_user — его нельзя забыть.
  - Данные о входе раздаются через Context (AuthProvider + useAuth), чтобы не передавать их по цепочке.
  - Две защиты: Stack.Protected не пускает на чужие экраны, RLS в базе не отдаёт чужие данные. Главная — RLS: даже если обойти экран, данные не утекут.
- **Правила RLS:**
  - профиль — только свой;
  - дисциплины — свои (преподаватель) или те, на которые записан (студент);
  - пары — если видна дисциплина.
- **Проверка:** student1 видит 3 дисциплины, student2 — 2, преподаватель — свои 3; неверный пароль — ошибка; сессия сохраняется после перезапуска.

### Проблемы и решения

1. **«Element type is invalid… undefined»** → в src/app был пустой файл экрана без export default. Правило: каждый файл в src/app — это экран и должен экспортировать компонент.
2. **Лишний незащищённый экран home-draft** → удалил; черновик остался в истории Git.
3. **Ошибка в `{ email.trim(), password }`** → сокращённая запись объекта работает только для имён переменных; написал `email: email.trim()`.

### Чему научился

- Триггеры и функции PostgreSQL, политики RLS и auth.uid().
- Context и собственный хук useAuth.
- ScrollView для длинных списков, сортировка запросом .order().

## Компоненты и вкладки

- **Что сделал:** компоненты Button, Card, Pill, Screen, EmptyState; нижние вкладки для студента (Главная, Расписание, Задания, Оценки, Профиль) и преподавателя (Пары, Журнал, Профиль); экран профиля; вынес общие типы и функции.
- **Где в коде:** src/components/, src/app/student/_layout.tsx, src/app/teacher/_layout.tsx, src/app/*/profile.tsx, src/types/index.ts, src/lib/format.ts, src/lib/auth.tsx (signOut)
- **Почему так:**
  - Компоненты — чтобы вид элементов менять в одном месте и не копировать классы.
  - Варианты оформления хранятся в объектах Record с полными именами классов: Tailwind ищет классы как текст, собранные из кусков имена (`bg-${color}`) не сработают.
  - Компоненты экспортируются по имени, экраны — по умолчанию: роутер берёт экран из export default.
  - Общие типы в src/types — чтобы при изменении таблицы править тип в одном месте.

### Проблемы и решения

1. **Не найден модуль @expo/vector-icons** → в новом шаблоне Expo его нет; установил через `npx expo install @expo/vector-icons`.
2. **Ошибка типа color у иконок вкладок** → типы меню и иконок расходятся; указал `color as string`, так как меню всегда передаёт строку.
3. **Компонент ничего не рисует** → не было `return` в функции с фигурными скобками.
4. **Pill внутри Text** → блок нельзя класть в текст; сделал строку flex-row из Pill и Text.
5. **Заглушка для пустого списка не показывалась** → проверка стояла внутри map, который для пустого массива не выполняется; вынес её наружу.

### Чему научился

- Props, children, значения по умолчанию, необязательные параметры.
- Record для вариантов оформления, условные классы через шаблонные строки.
- Tabs и иконки Ionicons; flex-row для строк.
